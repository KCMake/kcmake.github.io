Free Curb ATL: a map of free street parking

Python · JavaScript · Leaflet · GitHub Actions · 2026

Open the live map View the code

The Problem

Finding free street parking around Georgia Tech and Midtown is mostly guesswork. Many nearby streets are free, but Atlanta does not publish where its parking meters are, so there is nothing to look up. The quick fix of "every street minus the paid ones" is wrong: it marks interstates, park drives, and permit-only streets as free.

The Process

I started from the city's own street centerlines and classified each of 2,035 blocks by the strongest evidence available. Hard exclusions come first, so no rule can make a highway free. Next come 63 on-street listings that I checked by hand, then district-level rules for meter zones, permit neighborhoods, and campus. When the evidence is thin, a block is marked "check the signs" instead of free.

The page also knows the meter clock. City meters run Monday to Saturday, 7 AM to 10 PM, and are off on Sundays and nine holidays, so you can pick any day and time and see which curbs are free right then. Pick a destination, such as Tech Square, and it lists the six closest free blocks with walking times and directions.

What went wrong, and how I fixed it

  • The city's server silently dropped street segments (993 of 1,762 came back). I rewrote the fetcher to page by object ID and fail loudly if the counts do not match.
  • Parkopedia files free listings under a "meter" web address, so reading the address as proof of a meter marked eight free blocks as paid. I now record each listing's real rule and pinned a test to it.
  • Some address ranges only covered one side of a street, so I match listings to the nearest range within 40 house numbers. 62 of 63 now match.

The Outcome

The result is a single static HTML page with no server, API keys, or tracking that colors 285 km of curb, works on phones, and supports light and dark mode. Every block's popup shows its source and whether the rule was confirmed or inferred. Python and JavaScript test suites run in continuous integration on every push, and the map deploys to GitHub Pages automatically. I was careful to be honest about confidence: of 56.5 km marked paid, only 4.1 km is confirmed block by block, and the map says so.

AgriNexus 2.0: a smart nitrogen management system

Team Lead · ESP32-S3 · TinyML · Python · TSA Engineering Design, 2025 (top five in Georgia; national conference in Nashville)

The Problem

Farmers lose a lot of the nitrogen they apply: global use efficiency is only about 55%, so roughly 45% leaches into waterways or escapes as gas. That wastes money and feeds problems like algal blooms and dead zones. Existing fixes were either too large, like industrial ammonia production, or too manual for small growers.

The Process

Our team first explored three ideas: a sensor grid, an aquaponics loop, and a small-scale Haber-Bosch reactor, which we modeled in CAD. We dropped the reactor because it needs too much energy and infrastructure for local farms, and moved to a sensor-guided tray. AgriNexus 2.0 uses an ESP32-S3, a capacitive moisture probe, a BME280 climate sensor, and MOSFET-driven micro-pumps, all running on three AA batteries.

The key software step was replacing a fixed moisture threshold with a small machine-learning model. I helped train a linear regression in Python on logged tray data and exported its weights to a C++ header, so the ESP32 predicts moisture ten minutes ahead and waters before the soil dries out.

What went wrong, and how we fixed it

  • Our 3D-printed wedge warped in mild heat and tilted the tray, so we replaced it with hardwood shims and moved large parts to wood.
  • Tubing leaked in a 12-hour soak test, so we added silicone grommets and zip ties.
  • The touchscreen froze whenever pumps and sensors ran together, so we moved the display into its own FreeRTOS task.
  • A Python model file could not run on the microcontroller, so we extracted the weights by hand into a header file.

The Outcome

In a three-week test against a control tray, AgriNexus plants grew about 2 cm taller while using about 28% less water and 18% less fertilizer. The prediction logic cut redundant watering by 40% in cool-room tests. A companion web app shows live readings, history, and alerts.

ITrade: auditable AI trading agents In progress

Python · Docker · Model Context Protocol · OAuth 2.0 · Linux

An open-source framework for letting AI agents trade without losing track of what they did. The idea is that an autonomous agent with access to money should leave a record of every action and stay inside hard limits.

  • Brokerage integration over the Model Context Protocol, using OAuth 2.0 credential flows.
  • Per-action logging and rate limits, so every decision can be audited later.
  • Agents run in an isolated Docker sandbox on a cloud Linux VM, which contains anything an autonomous run does wrong.
